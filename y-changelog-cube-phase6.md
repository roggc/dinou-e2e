# Changelog — Dinou `10.0.5` (Phase 6 — Exhaustive Revalidation Matrix Hardening)

All notable core bug fixes uncovered and resolved during Phase 6 (`y-phase6-cube-tests.md`, Checks `#79–#84`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [10.0.5] - Unreleased

### Fixed

#### `revalidatePath()` Route Groups, Optional Catch-All `[[...slug]]`, Relative Headers & Monotonic Timestamps (`Check #79`)
- **Fixed `revalidatePath()` and `revalidateLayout()` canonical layout resolution for `(group)` and 0-segment `[[...slug]]` / `[[param]]` segments, Web `Headers` relative path resolution, and monotonic `revalState.lastGenTime` tracking** (`dinou/core/cache-revalidate.js`):
  - `revalidatePath()` previously probed `${cleanPathKey}/layout.rsc` directly and fell back to `getFilePathAndDynamicParams(..., "layout", true, true)`, which silently resolved to the **parent** shared layout (`ca/layout.rsc`) instead of the co-located 0-segment `[[...slug]]` layout (`ca/[[...slug]]/layout.rsc`) when calling `revalidatePath("/ca")`, and missed co-located layouts inside route groups (`grp/(alpha)/sub/layout.rsc` or `grp-home/(index)/layout.rsc`) while risking phantom keys outside the group. Updated `revalidatePath()` to resolve the active page and `getActiveLayoutChain()` leaf layout, matching co-located layouts via directory equality or `stripVirtualLayoutSegments(cleanLayoutKey) === decodedCleanKey` (which strips both `[[...]]` and `(group)` virtual markers), and calling `revalidateLayout(leafLayout.layoutRoutePath)` directly — while supporting explicit layout-only route-group targets (e.g. `revalidatePath("/grp/(alpha)")`) and preserving standalone storage-only fallback.
  - Replaced `stripEmptyOptional()` in `revalidateLayout()` with `stripVirtualLayoutSegments()`, allowing `revalidateLayout("/grp/sub")` and `revalidateLayout("/grp-home")` to resolve cleanly to their canonical `(group)` storage keys (`grp/(alpha)/sub`, `grp-home/(index)`) instead of emitting phantom keys outside the group.
  - Updated `normalizeRevalidatePath()` to support Web Standard `Headers` instances (`.get(...)`) as well as capitalized `Referer` headers when resolving relative paths (`./`, `../sibling`).
  - Synchronized `revalState.lastGenTime = Math.max(revalState.lastGenTime, commitLayoutGenTime)` at layout commit time so rapid back-to-back same-millisecond `revalidatePath()` calls always advance layout and page `generatedAt` / `window.__DINOU_BUILD_ID__` strictly monotonically.

#### `revalidateTag()` Cloudflare Workers Ancestor Ordering, `slotBackups` Metadata Rollback & `ownSlotTags` Discovery (`Check #80`)
- **Fixed concurrent ancestor-ordering race on Cloudflare Workers, incomplete `slotBackups` metadata rollback on partial slot failures, and `ownSlotTags` layout matching in `revalidateTag()`** (`dinou/core/cache-revalidate.js`):
  - `revalidateTag()` previously invoked `await Promise.all(sortedTargetLayouts.map(...))` (and `Promise.all` on `targetPaths`). On Cloudflare Workers (`isCloudflareWorkersRuntime() === true`), where `enqueueRevalidation()` intentionally bypasses the cross-request serial queue, ancestor (`L1`) and descendant (`L2`/`L3`) layouts executed concurrently in parallel — allowing a fast child layout to recompose stale `L1` before a slow `L1` committed. Replaced both layout and page revalidation loops with sequential `for ... of` iteration over `sortedTargetLayouts` and `targetPaths` (in both storage and legacy filesystem branches), guaranteeing strict ancestor-first execution on all runtimes.
  - `slotBackups` rollback in `revalidateTag()` previously snapshotted only `slots/${sid}/slot.json` without reading `slots/${sid}/slot.metadata.json` when `prevJson.metadata` was absent (as on `FileSystemStorage` or split-key KV backends), restoring failed slots with bare `{ slotId }` and losing their `tags`, `revalidate`, and `inStaticShell` metadata — preventing subsequent `revalidateTag()` calls on cold pods from finding the recovered slot. Updated `slotBackups` to snapshot and restore BOTH `slot.json` and full `slot.metadata.json`.
  - Updated `revalidateTag()` layout metadata scanning to check `meta.ownSlotTags` in addition to `meta.slotTags` so static layouts underneath dynamic ancestors (`hasDynamicAncestor: true`) are always discovered when their slots are invalidated.

#### `revalidateLayout()` / `revalidatePage()` No-Op Guards, Stampede Deduplication & PPR Causal `_old` Hydration Snapshots (`Check #81`)
- **Fixed phantom artifact writes on non-existent / dynamic routes, added `inflightPageRevalidations` deduplication, and implemented PPR causal `shell.*._old.json` serving on initial `____build_id____` hydration** (`dinou/core/cache-revalidate.js`, `dinou/core/handler.js`):
  - `revalidateLayout("/does-not-exist")` and `revalidateLayout("/leaf-without-own-layout")` previously fell back to `getFilePathAndDynamicParams(..., finalDestination = false)` which climbed up to root `src/layout.tsx`, rendered root layout via `getJSX()`, and wrote phantom `layout.rsc` / `shell.layout.json` / `layout.metadata.json` files under the non-existent path while returning `true`. Removed the ancestor climb fallback and returned `false` immediately whenever `!leafEntryPre && !cached && !hasCachedMeta`.
  - `revalidatePage()` previously ran ancestor layout checks and storage tombstones for non-existent paths and cached `revalidate < 1` dynamic pages on explicit calls, and lacked concurrent in-flight deduplication. Added an early no-op return when `!pagePath && !cached && !existingPageRsc`, added a dynamic page bailout guard when `effectivePageReval < 1`, and added `inflightPageRevalidations` deduplication (skipping dedup on Cloudflare Workers to prevent cross-request `IoContext` leaks).
  - `handler.js` PPR RSC delivery (`/____rsc_layout____` & `/____rsc_page____` when `isRoutePpr === true`) previously ignored `internalBuildId` (`____build_id____=T1`) and always read current `shell.layout.json` / `shell.page.json` while running `refreshNestedSlotsInTree()`, causing React `#418` hydration mismatches if a revalidation advanced the server from `T1` to `T2` while a client was still hydrating `T1` SSR HTML. Added `useOldPprShell` routing to `shell.layout._old.json` / `shell.page._old.json` when `Number(internalBuildId) < Number(currentGeneratedAt)` and skipped `refreshNestedSlotsInTree()` during initial causal `____build_id____` hydration.

#### `refreshSlot({ fresh: false | true })` & `refreshSlot("*")` Query Parsing, Early `isNoCache`, Nonce-Scoped Dedup & Cross-Route Shared Slot Sync Ordering (`Check #82`)
- **Fixed `?fresh=0`/`?fresh=false` parsing, early `isNoCache` bypass before `inflightSlotRenders`/`recentFreshSlotRenders`, `<500ms` stale fresh-slot caching, same-ms cross-route `nextSlotGenAt` monotonicity, and lazy layout HTML re-composition masking cross-route shared page slots** (`dinou/core/handler.js`, `dinou/core/cache-slot.js`, `dinou/core/cache-revalidate.js`):
  - `handler.js` previously computed `isFresh` using `urlObj.searchParams.has("fresh")`, causing explicit `?fresh=0` and `?fresh=false` requests to `/____rsc_slot____/:id` to be misclassified as `fresh = true`. Updated parsing to treat `"0"` and `"false"` as `isFresh = false`.
  - `getSlotJSX()` (`cache-slot.js`) previously checked `inflightSlotRenders` and `recentFreshSlotRenders` at lines `1137–1152` **before** checking `isNoCache` (`revalidate < 1`), and cached ALL `{ fresh: true }` renders for 500ms even when no unique request nonce (`?t=...`) was present — causing rapid `<500ms` sequential `getSlotJSX(id, { fresh: true })` or bare `?fresh=1` requests to return stale `V2` after mutating state to `V3`. Added early `isEarlyNoCache` guard before `inflightSlotRenders`/`recentFreshSlotRenders` and scoped `recentFreshSlotRenders` strictly to requests carrying a `?t=` nonce (still coalescing duplicate React StrictMode reads of the same client request while never returning stale results for distinct fresh requests).
  - Synchronized `nextSlotGenAt` in `getSlotJSX()` with `revalState.lastGenTime` so a slot refreshed on `Page A` always advances strictly past a peer `Page B`'s `generatedAt` even within the same millisecond (`inspectSlotsFreshness().hasNewer`).
  - **Direct SSR cross-route shared slot masking fix**: `handler.js` previously executed lazy layout-newer HTML re-composition (`leafLayout.generatedAt > pageGeneratedAt`, setting `page/metadata.json.generatedAt = leafLayout.generatedAt` with the stale `page.rsc`/`shell.rsc`) **before** checking `inspectSlotsFreshness(cachedItem.metadata.slotTags, cachedItem.metadata.generatedAt)`. Whenever `refreshSlot("*")` (or concurrent slot refreshes) updated a shared page slot (`T_slot`) and then an ancestor layout slot (`T_layout > T_slot`), Direct SSR to a peer route (`Page B`) sharing that slot first bumped `Page B`'s `generatedAt` to `T_layout > T_slot`, causing `inspectSlotsFreshness` to evaluate `hasNewer === false` and permanently serve stale pre-refresh slot HTML (`100`) on `Page B`. Fixed by: (a) recording `pageSlotsGeneratedAt` in `revalidatePage()` (`cache-revalidate.js`) and preserving it untouched during layout-only lazy HTML re-composition (`handler.js`), (b) moving the Direct SSR `inspectSlotsFreshness` -> `revalidatePage({ onlyRefreshSlots: true })` sync **before** lazy layout HTML re-composition, and (c) using `pageSlotsGeneratedAt || generatedAt` as the freshness baseline in both Direct SSR and non-PPR `/____rsc_page____` handlers.

#### Clock-Based TTL (`revalidate = N`) Per-Param `revalidate(params)`, Mid-ISR Dynamic Bailout Eviction & Ancestor-First Slot SWR (`Check #83`)
- **Fixed per-param `revalidate(params)` evaluation across SSG/runtime/revalidation, mid-ISR dynamic bailout stale-artifact eviction across pods, and sequential ancestor-first background layout-slot SWR** (`dinou/core/layout-functions.js`, `dinou/core/build-static-pages.js`, `dinou/core/cache-revalidate.js`, `dinou/core/handler.js`, `dinou/core/revalidating.js`):
  - `layout-functions.js:162`, `cache-revalidate.js:361`, `build-static-pages.js:75,1355,1560,1750`, and `handler.js:627` previously invoked `revalidate()` **without passing `dParams`**, and `handler.js` cached the resolved `revalidateVal` & `isDynamic` once per `pagePath` in `pageFunctionsConfigCache` (causing `/dyn-fn/fast`, `/dyn-fn/slow`, and `/dyn-fn/live` to share the first request's TTL & dynamic mode). In addition, `build-static-pages.js` checked `isDynamicRoute(revalidate)` before expanding `getStaticPaths()` and allowed `|| isPpr` to override an explicit `revalidate < 1`. Updated all 4 files to pass `dParams`, evaluate `revalidateFn(dynamicParams)` per request in `resolvePageFunctionsConfig`, defer parameterized `revalidate(params)` checks until concrete `getStaticPaths` items are expanded, and strictly honor `revalidate < 1` as dynamic (`!isDynamicConfig`).
  - **Mid-ISR dynamic bailout metadata transition, causal `_old` preservation & cross-pod safety**: `revalidatePage()` (`cache-revalidate.js`) previously skipped dynamic bailout when `isRoutePpr === true` and did not persist `{ dynamic: true }` in `metadata.json` or purge stale `page.rsc`/`shell.html`/`shell.page.json`, leaving pre-bailout static artifacts live on cold pods and breaking PPR shell bailouts. Similarly, `revalidateLayout()` only wrote `dynamic: true` when `!hasCachedMeta`, failing to transition already-cached layouts on mid-ISR bailout. Updated both `revalidatePage()` and `revalidateLayout()` to handle bailout on both non-PPR and PPR shells, preserve causal `_old` snapshots (`page._old.rsc`, `index._old.html`, `shell.page._old.json`, `layout._old.rsc`, `shell.layout._old.json`) and keep physical `index.html` intact for concurrency safety (preventing in-flight stream breakage during Static↔Dynamic transitions while avoiding React `#418` for tabs hydrating `?____build_id____=T_prev`), evict stale RSC/PPR shell artifacts, and persist `metadata.json` / `layout.metadata.json` with `{ dynamic: true, generatedAt: nextMonotonicGenTime(...) }`, which `handler.js` honors on Direct SSR, Step 2b PPR recovery, and `/____rsc_page____` across warm and cold pods.
  - **Sequential ancestor-first background layout-slot SWR & `ownSlotTags` parity**: Updated `handler.js` (Direct SSR, RSC layout pre-sync, and asymmetric SSR under dynamic layouts) to merge `ownSlotTags` + `slotTags`, check `pageSlotsGeneratedAt` in asymmetric SSR and `revalidating.js`, and chain deferred expired layout-slot SWR refreshes sequentially inside a single background `ctx.waitUntil` promise so multi-level layout slot cascades stay ancestor-first even on Cloudflare Workers.

#### Trigger Surfaces (Server Functions, Webhooks, Standalone Workers) × Distributed Multi-Pod & Edge Runtimes (`Check #84`)
- **Fixed Pass C `dinou.config.*` duplicate non-RSC bundling & `dinou/server` RSC API delegation, evicted-layout regeneration after standalone worker `revalidateLayout()`, cross-pod `revalidateTag()` slot detection & `slot.metadata.json` sync on KV/Redis, Cloudflare `env.ASSETS` tag-resurrection guard, and ancestor-first host layout refresh ordering** (`dinou/node/build.js`, `dinou/node/bundle-dual-engine.js`, `dinou/cloudflare/build.js`, `dinou/deno/build.js`, `dinou/bun/build.js`, `dinou/server.js`, `dinou/core/get-jsx.js`, `dinou/core/handler.js`, `dinou/core/cache-slot.js`, `dinou/core/storage-adapter.js`):
  - **Pass C `dinou.config.*` non-RSC duplication & `dinou/server` delegation (`node/build.js`, `node/bundle-dual-engine.js`, `cloudflare/build.js`, `deno/build.js`, `bun/build.js`, `server.js`, `get-jsx.js`, `cache-slot.js`)**: Both Pass A (`rsc-engine.mjs`, compiled with `react-server` + `clientReferencesPlugin`) and Pass C (`.dinou/node/server.mjs`, `.dinou/dist1/server/handler.js`, `.dinou/netlify/functions/ssr.mjs`, compiled WITHOUT `react-server` or `clientReferencesPlugin`) previously imported `dinou.config.*`, executing top-level config code twice and letting Pass C overwrite `globalThis.__DINOU_AOT_CONFIG__` / `globalThis.__DINOU_CONFIG__` with non-RSC plugin closures bundling a raw copy of `cache-revalidate.js` → `get-jsx.js` → `slot.js`. Calling `revalidateLayout()` (or `revalidatePath()`/`revalidateTag()` targeting a layout) from a `dinou.config.*` `onRequest` webhook under `npm run start:node:esbuild` then threw `Error: Could not find the module "file:///.../.dinou/node/slot.js#DinouPageSlot" in the React Client Manifest`. Fixed with a 3-layer defense: (1) Pass C no longer re-imports or overwrites `dinou.config.*` and instead reads the single Pass A RSC-compiled config from `globalThis.__DINOU_AOT_CONFIG__`, (2) all Dual-Bundle RSC entries (`node`, `cloudflare`, `deno`, `bun`) publish their RSC-compiled `{ revalidatePath, revalidatePage, revalidateLayout, revalidateTag }` onto `globalThis[Symbol.for("dinou.revalidation.api")]` and `dinou/server.js` delegates to it whenever an active RSC engine (`__DINOU_EDGE_RENDERER__`) is loaded (falling back cleanly to standalone `cache-revalidate.js` in out-of-band worker processes), and (3) `createDinouPageSlotElement()` (`get-jsx.js`) and `getCacheSlotBoundary()` (`cache-slot.js`) resolve `slot.js` `fileUrl` from `globalThis.__DINOU_CLIENT_MANIFEST__` (and check `__DINOU_EDGE_RENDERER__.registerClientReference`) before falling back to `path.resolve(currentDir, "slot.js")`.
  - **Evicted static layout & cross-process PPR shell recovery (`handler.js`)**: When an out-of-band standalone worker process (or cross-pod eviction) called `revalidateLayout("/L1")` and evicted `L1/layout.*` while child `page/index.html` remained cached, `handler.js` previously saw `lMeta === null` (`generatedAt = 0`), skipped regeneration, and served stale `L1` indefinitely inside child pages. Direct SSR (`activeLayoutChain`) and RSC layout pre-sync now detect `!entry.hasMeta && !entry.isDynamicConfig`, regenerate the evicted static layout via `revalidateLayout()`, and lazily recompose the child page HTML with the fresh layout while keeping the child page shell frozen. Likewise, when a standalone worker evicted a PPR page's `shell.html` / `index.html` directly on disk without setting in-process `_deletedKeys`, Step 2b PPR shell regeneration previously skipped static-path PPR routes and fell through to full `getJSX()` (re-executing untouched cached ancestor layouts); Step 2b now runs for any missing static PPR page (`Boolean(pagePath) && (isShellDeletedInStorage || !hasDynamicUrlParams || allowISGValue !== false)`), preserving cached ancestor `layout.rsc` untouched.
  - **Cloudflare Workers `env.ASSETS` stale-tag resurrection guard (`handler.js`)**: `handler.js` previously hydrated build-time `env.ASSETS` HTML into `DINOU_CACHE` KV without checking `storage.getTagInvalidatedAtAsync()` against `metadata.tags` / `slotTags` / `ownSlotTags` — allowing a cold isolate to resurrect stale build HTML after another isolate invalidated a tag before first KV hydration. Added tag-invalidation verification matching `readDist2Fallback()` before accepting `env.ASSETS` HTML.
  - **Distributed KV/Redis slot metadata parity & `ownSlotTags` (`cache-slot.js`, `storage-adapter.js`)**:
    - Persisted `slots/${id}/slot.metadata.json` alongside `slot.json` on non-FS distributed adapters (`RedisStorage`, `DenoKVStorage`, `CloudflareKVStorage`) so cold pods never fall back to stale `.dinou/dist2/slots/${id}/slot.metadata.json`.
    - Updated `inspectSlotsFreshness()` (`cache-slot.js`) to check `getTagInvalidatedAtAsync()` (in addition to `isKeyDeleted()`) when a slot is missing in storage so cross-pod `revalidateTag()` invalidations always trigger `hasNewer = true`.
    - Sorted `candidateLayoutKeySet` ancestor-first in `getSlotJSX()` host layout persistence (`cache-slot.js`) and added `ownSlotTags` to `readDist2Fallback()` (`storage-adapter.js`).
