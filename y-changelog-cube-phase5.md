# Changelog — Dinou `10.0.5` (Phase 5 — Remaining Orthogonal 3D Caching Cube & Runtime Parity Hardening)

All notable core bug fixes uncovered and resolved during Phase 5 (`y-phase5-cube-tests.md`, Checks `#73–#78`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

---

## [10.0.5] - Unreleased

### Fixed

#### Unbundled Classic Node Runtime (`isEdgeRuntime() === false`) & `revalidating.js` 3D Cube Parity
- **Brought unbundled / classic Node execution (`DINOU_RUNTIME` unset) and `revalidating.js` to full 3D Caching Cube parity** (`dinou/core/revalidating.js`, `dinou/core/handler.js`, `dinou/core/rsc-renderer.js`, `dinou/core/cache-revalidate.js`, `dinou/core/generate-static-page.js`, `dinou/node/bundle-dual-engine.js`):
  - `dinou/core/revalidating.js` previously inspected only root `metadata.json` (`revalidate` / `generatedAt`) — ignoring `pageRevalidate`, `pageGeneratedAt`, per-level `layout.metadata.json` (`ownGeneratedAt` + `revalidate`), and `<DinouCacheSlot>` `slotTags` — and regenerated via legacy `buildStaticPage()` → `generateStaticRSC()` → `generateStaticPage()`, which bypassed `runWithPprContext`, omitted `shell.page.json` / `shell.layout.own.json` preservation, and could downgrade PPR routes to non-PPR HTML. Rewrote `revalidating()` to inspect both active ancestor layout chains (`layout.metadata.json` TTL + slot freshness) and page `metadata.json` via `getStorageAdapter()`, delegating expired layouts/pages/slots to `revalidateLayout()` (ancestor-first with `recomposeOnly` for non-expired child layouts) and `revalidatePage()` while preserving all 3D PPR shells, `_old` causal snapshots, and `isDynamicFromServer` bailout state.
  - Removed obsolete `isEdgeRuntime(platformContext)` gates in `dinou/core/handler.js` that caused classic Node (`DINOU_RUNTIME` unset) requests to skip per-level layout TTL/slot freshness checks, skip `StorageAdapter` RSC delivery (falling back to raw `readFileSync` with `application/octet-stream`), skip PPR shell hole splicing (`spliceDynamicHolesIntoShell`), skip asymmetric `S → D` layout composition on `/____rsc_layout____`, and fall through to `HTTP 500: No renderer available` on dynamic/asymmetric/ISG SSR routes whenever `renderHtmlStream` was available; added `shell.html` fallback on the pure-disk SSR branch as well.
  - Updated `renderRSCStream()` and `pipeRSC()` (`dinou/core/rsc-renderer.js`) to honor an active Dual-Bundle renderer (`globalThis.__DINOU_EDGE_RENDERER__`) even when `isEdgeRuntime()` is `false`, preventing `@roggc/react-server-dom-esm/server` crashes on webpack-style client references while keeping `isEdgeRuntime()` strictly `false` for standalone worker detection.
  - Updated `dinou/core/generate-static-page.js` to pass `isSSG: true` when generating `shell.rsc` so live PPR dynamic hole data is never baked into `shell.rsc`.
  - Updated `dinou/core/cache-revalidate.js` to recognize a loaded route engine (`globalThis.__DINOU_ROUTE_MAP__`) when checking missing leaf layouts and to include `shell.page._old.json` in standalone worker eviction lists, and exported `revalidatePath`, `revalidatePage`, `revalidateLayout`, `revalidateTag`, `revalidating`, and `regenerating` from `rsc-entry.mjs` (`dinou/node/bundle-dual-engine.js`).

#### Static Site Export (`dinou export-static`) Under 3D Caching Cube Topologies
- **Hardened static-export RSC URL encoding, `refreshSlot()` graceful no-op, `layoutCache` miss recovery, and `reset_layout` client layout discovery** (`dinou/core/client.jsx`, `dinou/core/client-webpack.jsx`, `dinou/core/slot.js`, `dinou/core/discover-layouts.js`):
  - `buildStaticExportRscUrl()` (`client.jsx`, `client-webpack.jsx`) previously concatenated raw `layoutKey` segments when constructing static-export `.rsc` URLs, emitting unencoded `[` / `]` brackets for 0-segment optional catch-all layouts (`[[...slug]]/layout.rsc`) which strict RFC 3986 parsers and static hosts can reject. Updated `buildStaticExportRscUrl()` to percent-encode each pathname segment via `encodeURIComponent(safeDecodeSeg(seg))` (emitting `%5B%5B...slug%5D%5D/layout.rsc` while keeping `(group)` segments literal and avoiding double-encoding).
  - `refreshSlot()` and `fetchSlotRSC()` (`client.jsx`, `client-webpack.jsx`) plus the `dinou:refresh-slot` dispatcher (`slot.js`) previously attempted live `fetch("/____rsc_slot____/...")` requests even when `window.__DINOU_STATIC_EXPORT__ === true`, causing static hosts to return 404 HTML and triggering React Flight parse errors. Guarded all three to resolve/return cleanly as a safe no-op in static-export (and document-unloading) mode, and evicted failed static-export layout fetches from `layoutCache` to prevent stale prefetch poisoning.
  - `discoverLayoutsFromFileRelPaths()` and `discoverLayoutsFromFs()` (`discover-layouts.js`) previously tracked `layout` and `no_layout` files but did not stop climbing at `reset_layout` directories: a page inside a `reset_layout` folder without its own `layout.tsx` erroneously inherited an outer ancestor layout in `getLayoutKey()`. Added `resetLayoutDirs` tracking so layout discovery stops cleanly at `reset_layout` boundaries, matching server-side `getActiveLayoutChain()`.

#### Perimeter Guards (`validateParams`, `allowISG = false`, `getProps` `redirect()` & 404 Composition Under 3D PPR)
- **Preserved cached unblocked ancestor PPR layouts, valid React Flight 404 payloads, SSG 404/blocked hygiene, optional/catch-all descendant routing, and revalidation isolation on perimeter-blocked and redirecting routes** (`dinou/core/handler.js`, `dinou/core/cache-revalidate.js`, `dinou/core/get-file-path-and-dynamic-params.js`):
  - `handler.js` previously responded with plain-text `"Not Found"` (`status: 404`) on both SSR and `/____rsc_page____` / `/____rsc_layout____` endpoints whenever `validateParams()` returned `false` or `allowISG = false` rejected an unbuilt param — causing client soft `<Link>` navigations to crash React Flight deserialization (`createFromFetch`) instead of rendering `not_found.tsx`, and preventing Direct SSR from rendering `not_found.tsx` wrapped in cached unblocked ancestor layouts. Tracked the exact blocked layout index (`blockedLayoutIdx` / `blockedLayoutAncestors`) so both SSR and RSC emit HTTP `404` with `not_found.tsx` (and valid `text/x-component` Flight streams on RSC) composed strictly inside unblocked cached ancestor layouts (`shell.layout.own.json` + live PPR holes) without ever executing the blocked layout/page or writing cache files, and set `window.__DINOU_ACTIVE_LAYOUT__` on SSR when a child layout is blocked so initial hydration matches cleanly.
  - Hardened `shouldCacheISG` (`handler.js`) so SSG (`platformContext.isSSG === true`) also requires `!isNotFound.value && !isPathBlocked && genMeta.status === 200` before persisting `index.html`/`page.rsc` into storage (preventing `404` or perimeter-blocked responses from ever being frozen into `.dinou/dist2`).
  - Updated uncached PPR `/____rsc_layout____` fallback (`handler.js`) to reuse cached ancestor `shell.layout.own.json` fragments via `composeLayoutChainFromOwnFragments()` instead of falling back to raw `getJSX()` (which previously re-executed poisoned cached `L1` layouts on soft `<Link>` navigation to uncached `[id]` or redirecting routes), and short-circuited Pass 2 `3xx` redirects in cold PPR ISG after cleaning up `newlyPopulatedLayoutKeys` (including `_old` snapshots).
  - Updated `revalidatePage()` and `revalidateLayout()` (`cache-revalidate.js`) to validate ancestor layout and page `validateParams` / `allowISG = false` contracts and to bail out immediately whenever `redirect()` is invoked (including on PPR routes), preventing on-demand revalidation calls from rendering or persisting blocked or redirecting routes into storage.
  - Fixed `matchRouteTree()` and `getLayoutsForLayoutKey()` (`get-file-path-and-dynamic-params.js`) to backtrack on optional single dynamic (`[[param]]` → 0 segments / `undefined`), required catch-all (`[...param]` → longest down to 1 segment), and optional catch-all (`[[...param]]` → longest down to 0 segments / `[]`) directories when descendant routes exist underneath them (e.g. `opt/[[locale]]/about/page.tsx` at `/opt/about`, `ca/[...section]/view/page.tsx` at `/ca/guides/auth/view`, `oca/[[...seg]]/doc/page.tsx` at `/oca/doc` and `/oca/v1/api/doc`), which previously returned `404` and were silently masked by SSG caching non-200 pages.

#### React 19 `useId()` Collision & Scoped-ID Hydration Integrity Across 3D PPR & `<DinouCacheSlot>`
- **Eliminated Client `useId()` hydration mismatches (`#418`) and Server `useId()` cross-segment collisions inside PPR streaming holes and asymmetric layouts** (`dinou/core/ppr-runtime.js`, `dinou/core/render-jsx-to-client-jsx.js`):
  - `streamDynamicHoles()` (`ppr-runtime.js`) previously rendered each resumed PPR dynamic hole in an isolated standalone `renderToReadableStream(resolvedChildren)` pass rooted at `TreeContext` `0`, causing every Client Component calling `React.useId()` inside separate PPR holes to emit colliding `_R_0_` DOM IDs and immediately fail React 19 client hydration (`#418`) against the real full-document `TreeId` computed by `hydrateRoot()`. Added `buildPprHoleSkeleton()` and `extractPprHoleHtml()` in `ppr-runtime.js` to reconstruct a minimal ancestor-path skeleton (`React.Fragment` + `null` sibling slots + ancestor user Client Components + `<dinou-ppr-extract>`) from `shell.layout.json` / `shell.page.json` for each streaming hole, generating bit-for-bit identical React 19 `TreeId` values while preserving 0ms shell TTFB and staggered hole streaming.
  - `useServerId()` (`render-jsx-to-client-jsx.js`) previously formatted runtime hole IDs as `_hole_<holeId>_dS_<n>_` without incorporating the active layout or page segment scope, causing Server Components calling `React.useId()` inside an `L1` PPR hole (`ppr-hole-1`) and an asymmetric `Page` PPR hole (`ppr-hole-1`) — or inside two distinct dynamic layouts' `<Suspense>` boundaries (`layout-hole-1`) — to generate colliding IDs. Scoped hole server IDs to `_page_hole_<holeId>_dS_<n>_` vs `_layout_<scopePrefix>_hole_<holeId>_dS_<n>_` and propagated layout/page segment stores during `streamDynamicHoles()` traversal.

#### `error.tsx` & Client `ErrorBoundary` Fault Isolation, `reset()`, and Soft-Navigation Recovery Under 3D PPR + `<DinouCacheSlot>`
- **Fixed `error.tsx` `reset()` injection, client error-cache eviction, and cached ancestor layout preservation on page/layout/PPR-hole faults** (`dinou/core/slot.js`, `dinou/core/get-error-jsx.js`, `dinou/core/client.jsx`, `dinou/core/client-webpack.jsx`, `dinou/core/handler.js`, `dinou/core/ppr-runtime.js`):
  - Server-rendered `error.tsx` payloads (from Direct SSR, `/____rsc_page____` 500, and `/____rsc_layout____` 500) previously passed no `reset` prop to client `error.tsx` components, and `SlotErrorBoundary`'s `reset()` merely toggled local React state without clearing errored `pageCache`/`layoutCache` entries or calling `router.refresh()`; additionally, `Router.refresh()` failed to clear `initialPageErrorRef.current` and `layoutKey`'s `useMemo` omitted `layoutVersion`, preventing Direct SSR error recovery via `reset()` from restoring a previously crashed nested layout (`L2`). Added `DinouErrorResetWrapper` (`slot.js`, registered via `get-error-jsx.js`) to inject a working `reset()` prop into every client `error.tsx`, tracked `5xx` and `x-dinou-has-error: true` responses (plus `data-dinou-ppr-error="true"` streaming PPR hole errors emitted by `PprDynamicHoleBoundary` in `ppr-runtime.js`) in `erroredPageCacheKeys` / `erroredLayoutCacheKeys` (`client.jsx`, `client-webpack.jsx`), evicted them on `navigate()`, `onPopState()`, and `refresh()`, cleared `initialPageErrorRef.current`, and included `layoutVersion` in `layoutKey`'s `useMemo` dependencies.
  - `handler.js` previously fell back to `getErrorJSX()` / raw `getJSX()` whenever a Page or Dynamic `L2` layout threw on Direct SSR or `/____rsc_layout____`, re-executing cached static/PPR ancestor `L1` layouts live (leaking poisoned state) and returning HTTP `200` on `/____rsc_layout____` (pinning the error layout in `layoutCache`). Updated both `/____rsc_layout____` and Direct SSR `isError` handling to compose healthy ancestor layouts from cached `shell.layout.own.json` fragments (+ live PPR holes) around `error.tsx` with HTTP `500` + `x-dinou-has-error: true`, keeping `L1` static shells, `<DinouCacheSlot>`s, and client probes 100% intact.

#### Standalone Compiled Single-File Binaries (`build:node:compile` × `build:bun:compile` × `build:deno:compile`) & Deno KV Seeding Parity
- **Fixed missing `shell.layout.own.json` / companion metadata in Deno KV pre-seeding and missing `DinouErrorResetWrapper` client-manifest normalization across all 4 runtimes + Dev** (`dinou/deno/seed-kv.js`, `dinou/node/bundle-dual-engine.js`, `dinou/bun/build.js`, `dinou/deno/build.js`, `dinou/cloudflare/build.js`, `dinou/node/dev.js`):
  - `dinou/deno/seed-kv.js` previously seeded `.rsc`, `shell.page.json`, and `shell.layout.json`, but omitted `shell.layout.own.json` (as well as `shell.layout._old.json` / `shell.page._old.json`) and only attached companion `layout.metadata.json` to `layout.rsc` (omitting companion metadata on `shell.layout.json`, `shell.layout.own.json`, `page.rsc`, and `shell.page.json`). In pure-KV deployments without local `.dinou/dist2` disk fallback (such as Deno Deploy or standalone `deno compile` binaries deployed with `.dinou/kv.db`), asymmetric 3D PPR layout chains (`S → D → S`) and sibling route-group layouts missed `shell.layout.own.json` in KV and fell back to re-executing cached ancestor layouts live. Updated `seed-kv.js` to seed `shell.layout.own.json`, `shell.layout._old.json`, and `shell.page._old.json` and attach companion `layout.metadata.json` / `metadata.json` across layout and page artifacts.
  - Added `${url}#DinouErrorResetWrapper` normalization to `normalizedManifest` across all four AOT Dual-Engine builders (`dinou/node/bundle-dual-engine.js`, `dinou/bun/build.js`, `dinou/deno/build.js`, `dinou/cloudflare/build.js`) and `dinou/node/dev.js` (including `dynamicSsrModuleMap`) alongside `DinouPageSlot` and `DinouCacheSlotBoundary`, ensuring server-rendered client `error.tsx` reset wrappers resolve identically across Esbuild, Rollup, Webpack, ejected, and non-ejected modes on all runtimes.
