# Changelog — Dinou `10.0.6` (Phase 7 — Final 3D Caching Cube Edge Frontiers)

All notable core bug fixes uncovered and resolved during Phase 7 (`y-phase7-cube-tests.md`, Checks `#85–#86`) are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [10.0.6] - Unreleased

### Fixed

#### Mid-ISR Non-200 Outcome Transitions (`200` → `404` / `410` / `302` / `307` / Thrown `dinou-internal-redirect`), Causal `_old` Hydration & Distributed/Edge Tombstones (`Check #85`)
- **Fixed mid-ISR `res.redirect()`, `res.status()`, thrown `dinou-internal-redirect`, `validateParams()` 404, and removed-route transitions across `revalidatePage()`, `revalidateLayout()`, Direct SSR, RSC endpoints, PPR holes, and distributed/Edge KV storage** (`dinou/core/cache-revalidate.js`, `dinou/core/handler.js`, `dinou/core/get-jsx.js`, `dinou/core/ppr-runtime.js`):
  - **Imperative `res.redirect()` & `redirect()` mid-ISR eviction bypass (`cache-revalidate.js`)**: Both `revalidatePage()` and `revalidateLayout()` previously returned early on `if (revalContext._hasRedirected)` / `if (layoutHasRedirected)` **before** reaching the dynamic bailout eviction & `metadata.json` (`dynamic: true`) tombstone block — leaving stale `200 OK` HTML/RSC/PPR shells pinned indefinitely on both Node pods and Edge/Redis pods. Removed the premature early return and routed redirects directly through the unified tombstone transition (`transitionPageToDynamicTombstone()` for pages, and symmetric layout tombstone persistence for layouts).
  - **No-op `revalContext.res.status()` during ISR regeneration (`cache-revalidate.js`)**: `revalContext.res.status` was previously an empty no-op (`status() {}`) in both `revalidatePage()` and `revalidateLayout()`, causing pages/layouts calling `getContext().res.status(410)` (or `404`, `403`, `451`, etc.) during ISR to be cached as `200 OK` static/PPR artifacts. Updated `revalContext.res.status(code)` to record `_statusCode` and trigger dynamic bailout (`markRevalDynamic()`) for any non-200 status code while returning `revalContext.res` for chaining.
  - **Thrown `dinou-internal-redirect` handling across revalidation, Direct SSR, RSC & PPR (`cache-revalidate.js`, `handler.js`, `get-jsx.js`, `ppr-runtime.js`)**:
    - `cache-revalidate.js` (`revalidatePage` and `revalidateLayout`) previously swallowed thrown `{ $$type: "dinou-internal-redirect", url }` objects inside generic `catch (e)` blocks — on Node this fell into `!didRenderFreshPage` and deleted `_old` snapshots (breaking causal hydration), while on Edge (`isEdgeRuntime() === true`) it skipped eviction and **re-stamped stale `200 OK` HTML with a fresh `generatedAt`**. Catch blocks now explicitly recognize `e?.$$type === "dinou-internal-redirect"` and route into the dynamic tombstone transition (and rethrow out of `revalidateLayout` step 3 so fallback rendering does not run).
    - `handler.js` (Direct SSR and `/____rsc_*` endpoints), `get-jsx.js` (layout/slot error-isolation catches), and `ppr-runtime.js` (dynamic hole catches) now recognize `{ $$type: "dinou-internal-redirect", url, status? }` and emit real HTTP `302`/`307` redirects (Direct SSR), `x-rsc-redirect` headers (soft-nav RSC), or PPR hole redirects instead of `500` error pages.
  - **Mid-ISR `notFound` (`validateParams() === false`, `isNotFound.value === true`, and removed `!pagePath` routes) across Node & Edge (`cache-revalidate.js`)**:
    - When `validateParams()` flipped from `true` to `false` mid-ISR on an already-cached route (`routeCfg.isBlocked && hasExistingPageArtifact`), `revalidatePage()` previously returned early without preserving `_old` snapshots, writing a `{ dynamic: true, notFound: true, status: 404 }` tombstone, or evicting stale `200` artifacts.
    - When `!didRenderFreshPage` (`isNotFound.value === true` or `!pagePath` on an already-cached route), `cache-revalidate.js` previously guarded eviction with `!isEdgeRuntime()` (causing Edge runtimes to skip eviction and actively re-persist stale `200 OK` HTML/RSC with an extended `generatedAt`) and deleted `_old` snapshots on Node. Now both Node and Edge preserve causal `_old` snapshots (`index._old.html`, `page._old.rsc`, `shell.page._old.json`), commit `{ dynamic: true, notFound: true, status: 404, generatedAt: T_next }` to `metadata.json`, and evict stale current artifacts — while preserving standalone out-of-band worker eviction semantics when `pagePath` still exists.
  - **Distributed/Edge KV inline `index.html` metadata & `.dinou/dist2` / `env.ASSETS` resurrection guard (`cache-revalidate.js`, `handler.js`)**:
    - On non-FS adapters (`!storage.baseDir`: `RedisStorage`, `DenoKVStorage`, `CloudflareKVStorage`, `MemoryStorage`), `storage.get(htmlKey)` returns the inline metadata saved on `htmlKey` itself rather than reading `metadata.json`, so keeping `htmlKey` intact during bailout caused Cold Pod B / Cold Isolate B to read stale `200` inline metadata and serve cached `200 OK` HTML indefinitely. `transitionPageToDynamicTombstone()` now keeps physical `index.html` intact on `FileSystemStorage` (`storage.baseDir`, where `get()` reads companion `metadata.json`) for concurrency safety, and deletes `htmlKey` and `cleanPathKey` on non-FS adapters (creating distributed KV/Redis tombstones).
    - `handler.js` Direct SSR now checks `storage.get(metaKey)` (`dynamic || notFound`) **before** falling back to Cloudflare `env.ASSETS` or `readDist2Fallback()`, guaranteeing zero stale `200` resurrection on Cold Pod B / Cold Isolate B even if a route was transitioned before first KV hydration.
  - **Recovery from `dynamic: true` / `notFound: true` back to `200` Static/PPR (`cache-revalidate.js`)**:
    - Both `revalidatePage()` and `revalidateLayout()` previously loaded `currentMeta` from `metadata.json` / `layout.metadata.json` and never cleared `currentMeta.dynamic` or `currentMeta.notFound` when a route/layout later recovered back to a healthy `200` static/PPR render — leaving recovered routes permanently stuck in dynamic mode. Both now explicitly clear `delete currentMeta.dynamic; delete currentMeta.notFound; currentMeta.status = 200;` upon committing a fresh static/PPR render.
  - **Poisoned `L1` layout preservation on Direct SSR after mid-ISR dynamic/410/404 transition (`handler.js`)**:
    - When `FileSystemStorage` kept physical `index.html` on disk with `metadata.json` `{ dynamic: true }`, `handler.js` cleared `dynamicState.value` at the start of Step 4 while `cachedItem` remained truthy, causing the asymmetric per-level layout composition guard (`!cachedItem || dynamicState.value`) to evaluate `false` and fall through to full `getJSX()` — re-executing cached/poisoned ancestor `L1` layouts. Tracking `hasMetadataDynamicTombstone` and clearing `cachedItem = null` on tombstoned hits ensures Step 4 always reuses cached ancestor `shell.layout.own.json` without re-executing `L1`, and prevents live SSR on a tombstoned PPR route from overwriting `shell.html` with a non-PPR full render before `revalidatePage()` restores it.
  - **Causal `_old` hydration protection on PPR routes & mid-ISR `validateParams()` flips (`handler.js`)**:
    - On PPR routes (`isRoutePpr === true`), `/____rsc_page____` and `/____rsc_layout____` previously skipped `shell.*._old.json` whenever `dynamicState.value === true` even for initial causal hydration requests (`?____build_id____=T1 < currentGeneratedAt`). Updated the PPR RSC branch to serve preserved `shell.*._old.json` (splicing holes inside an isolated sandbox context so newly added top-level `redirect()`/`res.status(410)` never mutates the hydrating client's bridge, with `page._old.rsc` fallback).
    - On `validateParams()` mid-ISR `200 → 404` (`isPathBlocked === true`), `/____rsc_page____` now serves preserved `page._old.rsc` / `shell.page._old.json` for in-flight tabs hydrating `?____build_id____=T1 < blockedMeta.generatedAt` (falling straight through to `404` `not_found.tsx` whenever no `_old` snapshot exists or on fresh requests without `____build_id____`).

#### React 19 Document Metadata Hoisting (`<title>`, `<meta>`, `<link>`) Inside Resumed PPR Dynamic Holes (`Check #86`)
- **Fixed React 19 hoisted document metadata being silently dropped or injected into `<body>` during Pure PPR streaming resume (`handlePprResume`)** (`dinou/core/ppr-runtime.js`):
  - **Dropped hoisted metadata in skeleton extraction (`extractPprHoleHtml` / `streamDynamicHoles`)**: When rendering a PPR dynamic `<Suspense>` hole wrapped in `<dinou-ppr-extract data-h="ppr-hole-N">` via React 19 `renderToReadableStream`, React 19 hoists `<title>`, `<meta>`, `<link>`, and precedence-scoped `<style data-precedence="...">` elements **out** of `<dinou-ppr-extract>` to the leading prefix of the rendered HTML stream. `extractPprHoleHtml()` previously sliced strictly between `<dinou-ppr-extract data-h="...">` and `</dinou-ppr-extract>`, silently discarding all document metadata emitted inside PPR dynamic holes on Pure PPR routes (`handlePprResume`).
  - **Misplaced metadata in non-skeleton fallback (`renderedViaSkeleton === false`)**: When skeleton extraction was unavailable, leading hoisted `<title>`, `<meta>`, and `<link>` elements remained inside `<template id="ppr-content-ppr-hole-N">` and were spliced into `<body>` via `t.replaceWith(c.content)` instead of `document.head`.
  - **Fix (`extractLeadingHoistedHeadHtml`, `extractPprHoleHtml`, `buildPprHoleChunk`)**: Added `extractLeadingHoistedHeadHtml()` to cleanly separate leading React 19 hoisted `<title>`, `<meta>`, `<link>`, and `<style data-precedence="...">` tags (leaving non-hoisted body tags such as `<meta itemProp>` and React Suspense comments `<!--$-->` untouched in `bodyHtml`, and never capturing ancestor Client Component wrapper elements in skeleton mode). When hoisted head markup is present, `buildPprHoleChunk()` emits a companion `<template id="ppr-head-ppr-hole-N">` whose inline script deduplicates against `document.head` and hoists the nodes into `<head>` (updating `<title>` in place without duplicates) before `hydrateRoot` adopts them with zero `#418` hydration errors.
